# Project CI

Phase 6 separates routine website and research checks from manually selected evidence, packaging and deployment preparation. See [the CI guide](../../CI.md) and [completion report](../../reports/GITHUB_PUBLICATION_PHASE6.md).

The exact completed Phase 5 selected-file seal is retained byte for byte as baseline-inputs.json. Its SHA-256 is pinned by verify_phase6.py. control-paths.json declares each new or modified Phase 6 path; all other Phase 5 inputs remain immutable. The current selected paths are publication/git-files.txt with its literal NUL pathspec. An independently trusted external seal authenticates the complete current selection; CI also compares every Git blob with the checkout. A commit cannot contain its own hash, so final head/run/seal hashes are saved in the external Phase 6 completion receipt.

The Phase 5 workflow is retained as a manual historical check of the pinned Phase 5 commit. It is no longer triggered by normal pushes or pull requests.

Current active source paths are enumerated as mutable controls, allowing ordinary code changes through pull requests. actual_modified_baseline_paths distinguishes actual Phase 6 changes from the broader permitted source scope in modified_frozen_input_paths. The verifier enforces a narrow source/control policy; metadata cannot exempt frozen artifacts, datasets, configuration, contracts, historical reports, requirements or vendor inputs. A future intentional evidence/protocol update requires a separately reviewed overlay. Add new paths to the exact selection and control lists; never force-add a directory. Accepted scientific evidence, archive policy, production snapshots and historical locks must not be regenerated by routine CI.

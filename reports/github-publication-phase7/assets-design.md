# Phase 7 research asset design and measured preparation

The Phase 3 selection permits eleven original archives and the ten-file notice companion. Phase 7 reuses those exact bytes; three UPF-containing archives remain excluded. No licence text, historical archive, scientific evidence, model state or historical selector was modified.

The existing public_assets.py verifier accepts a new selector under publication/phase7 while independently binding its Phase 3 policy, exact archive identities, historical member inventories, restoration namespaces, mandatory notice list and artifact_io implementation digest. The Phase 7 selector uses the stable v0.1.0 URLs. It is a prospective descriptor in the candidate; actual publication and retrieval must be proved by the final release transaction rather than inferred from metadata.

The repository is private. The new research_assets.py helper uses ordinary authenticated GitHub CLI operations, not anonymous HTTP or token-bearing URLs. It resolves the actual release tag to an immutable Git commit, requires a published release and checks the expected twelve names, sizes, server digests when present, states and stable URLs before downloading. Private archive names, raw UPFs and case-colliding names anywhere in the release metadata are rejected. Production package/inventory assets are checked separately by the complete release inventory rather than confused with the research subset.

Downloads use twelve literal patterns. Existing matching files can be reused; invalid/extra existing files are rejected, and no clobber option is used. Final local archive hashes and all ZIP members are verified using the unchanged audited verifier. The helper neither reads credential files nor prints, stores or embeds a credential. Report output is new and outside the source checkout.

Measured preparation: all twelve retained local archives passed a fresh Phase 7 full-member verification: 907 members, 4,157,779,365 archive bytes and 4,157,516,044 member bytes. The largest archive is 791,135,064 bytes. Local filenames, source paths, sizes and SHA-256 values are recorded externally in UPLOAD_RESEARCH_ASSETS.json. This verification read all selected members as bytes; it loaded no models and ran no scientific calculations.

Fifteen new metadata-boundary fixtures passed. They cover complete selection, extra separately verified production metadata, draft/wrong-tag rejection, private archives/raw UPFs, missing notices, duplicate/case collisions, changed sizes/digests, incomplete uploads, wrong repository URLs, missing server digest with mandatory later byte verification, unpublished selectors and unsafe tag syntax. An initial fixture exposed that the legacy basename utility permits only ZIP filenames; the new remote inventory checker instead validates a flat safe relative basename, allowing separate RELEASE.json/SHA256SUMS assets without weakening the research selection.
